## Decisions

- 2026-11-16: This repository is the open-source spin-out of the docla engine. It ships Claude Code skills (`brand`, `create`, `review`) and the engine they drive. There is no web interface. Reason: the owner's pivot; the interface stays in a private product.
- 2026-11-16: `docs/DESIGN.md` describes the skills, the editable copies and the review round trip; `docs/ENGINE.md` describes the engine. Where they differ, `docs/DESIGN.md` wins. Reason: the engine design was written for a local web application.
- 2026-11-16: The PDF is the deliverable and stays rendered by Typst. Every build also writes an editable copy for review only. Reason: the owner wants reviewers to edit text and comment in Word or PowerPoint, and to see the final PDF.
- 2026-11-16: The PowerPoint copy shows each slide exactly as the PDF does: a picture of the slide rendered with its text hidden, with every text field as a native editable text box at its measured position, named `<section-id>/<field-path>`. Reason: the owner's requirement that the deck copy looks like the slides; layout facts already give every field's box.
- 2026-11-16: The Word copy is text only: headings, paragraphs and lists inside bookmarks named by section id, with a one-line reference for each table, chart or figure. Reason: the owner's requirement; a document review is about wording.
- 2026-11-16: Checks and the look run on every build. There is no separate check skill. Reason: the owner's requirement that checking is automatic whenever something is written.
- 2026-11-16: Skills and agents make no model calls of their own. Commands a skill calls must not need an API key. Reason: the session's Claude is the model.
- 2026-11-16: A version is marked sent only when its look record has no open error and every page was looked at. A review copy is compared with the sent version, never with a fresh build. Reason: no version reaches a person unlooked-at. Superseded on 2026-11-17 (no sent mode, below).
- 2026-11-16: Formatting in a review copy is never applied; it becomes an emphasis hint. Text a reviewer wrote makes the section `owner="human"`; a comment becomes a `redraft=` ask and never pastes. Reason: keep the brand intact and keep the reviewer's words.
- 2026-11-16: The skills ship as a Claude Code plugin from this repository and call the engine through `bin/ai-docs-kit`, which runs the package with `uv` from the plugin folder. Reason: one install for skills and engine.
- 2026-11-16: Judges already in `tests/judge/` came over from docla and stay frozen. Golden facts files (`tests/fixtures/components/*.facts.json`) are regenerated with `scripts/golden_facts.py <name>`, never edited by hand. Reason: a hand edit hides a real layout change.
- 2026-11-16: Field paths follow `ai_docs_kit.render.marks.FIELD_PATTERN`, and anchors are section ids and field paths, never page numbers or boxes. Reason: edits and comments must survive re-rendering.
- 2026-11-17: The kit has two layers. The plugin's layer (engine, skills, agents, component library, neutral theme) is shared, read-only in use and replaced on update; the person's layer (the brand folder with its rulebook and `preferences.md`, working files, versions) is data the plugin reads and an update never writes, except a format migration the person runs. See `docs/DESIGN.md` section 10. Reason: people build their own brand and rules through the skills, and an update must not lose them.
- 2026-11-17: Skills never edit plugin files and never change the engine during a session. They read the brand's rulebook and `preferences.md` before their first step, and offer to record a repeated correction as a rule, a preference or an upstream issue. Reason: a local edit to a skill is silently wiped by the next update.
- 2026-11-17: A brand belongs to a project folder by default (`.brand/<slug>/`); `--root` points a project at a brand kept elsewhere. Reason: the owner's choice of default.
- 2026-11-17: The project is licensed under MIT, not Apache-2.0, and has no `NOTICE` file. Releases before this change stay available under Apache-2.0. Reason: the owner's choice; these are open-source skills, not the docla product, and every commit so far is the owner's.
- 2026-11-17: The brand's voice rules (`source.banned-terms`, `source.terminology-drift`) apply to `spoken`, but not to `note` or `source_line`. Reason: the audience hears `spoken`; `note` is private to the presenter and never shown, and a citation must keep the source's own wording, such as a report titled "Synergy report".
- 2026-11-17: There is no sent mode. A version has no `draft`, `ready` or `sent` state and nothing gates it; every version may be the one that goes out. The build, the look and `review apply` name plainly what the person needs to know: open errors, gaps, pages not looked at, and sections that changed or went missing since a review copy's version. A review copy is compared with the version it was built from, which the copy records. This supersedes the 2026-11-16 decision on marking a version sent and comparing with the sent version, and DESIGN.md principle S7. Reason: the owner's call; the gate and the staleness refusals added complexity without helping the person (#116 to #119).
- 2026-11-17: A reviewer's edits to bullet points in the Word copy are applied as the section's items, in order, including added and removed bullets. Reason: the owner's choice; otherwise list edits are dropped silently (#125).
- 2026-11-17: The Test command runs `mypy` in strict mode over `src/` (through `tests/judge/test_p0_1_tooling.py`) and builds real PDFs from the fixtures; the Check command runs `ruff` over the whole repository. There is no separate Smoke command, because the tests already build the real artefact. Reason: recorded once per project, as the loop asks.
- 2026-11-18: Preferences live only in the brand folder, in `preferences.md` headed `## All skills`, `## brand`, `## create` and `## review`, one dated line per entry in the person's words; each skill reads `All skills` and its own section. There is no personal preferences file outside the brand. Reason: the owner's choice; one place, as DESIGN.md section 10 says (#186).
- 2026-11-18: A skill files an upstream issue on this repository with `gh issue create` only after showing the person the text and getting a yes, and the text holds no brand material, document text or names from the person's project. Reason: the owner's choice; the repository is public (#186).
- 2026-11-18: `rule test` judges a rule against exactly the text `check` sees; a rule on `paragraphs` does not see bullet text. Reason: the owner's choice; otherwise a rule passes its test and never fires (#194).
- 2026-11-18: A section id whose Word bookmark name would exceed 40 characters gets a hashed name (`Xh_` plus a hash), and the copy stores the map from name to id in its custom properties. Reason: a review copy travels alone, so it must carry its own map (#189).

## Product rules

- British English. No em dashes. No agent attribution in commit messages or pull request text.
- Sign off every commit under the DCO (`git commit -s`).
- Every rule ships with a seeded defect: a fixture that fails it and one that passes it.
- A change that affects rendering attaches the rendered pages.
- Never patch generated files. Fix the source and rebuild.
- Never commit fonts or assets without a recorded licence; never commit secrets, credentials or generated PDFs.
- Never name, describe or copy material from a private project or a real brand. Test brands are synthetic.
- Prefer the standard library. A new dependency needs a licence check and a named reason (and is a stop, below).
- Python 3.12 or later, source in `src/ai_docs_kit/`, tests in `tests/`. Every change has a test that fails without it.
- Office files in tests are generated by the test (with python-docx and python-pptx, or by writing the XML parts), never committed binaries from a real tool, unless the issue names one.
- Numbers shown to a person must trace to a source fact; a chart or table must show what its data declares.
- A skill or agent file is plain Markdown with frontmatter; every command it names must exist and answer `--help`.

## Stops

An agent that needs one of these ends its reply with
`PARK: <question> | <recommended answer>` and stops work on the issue:

- spending money or changing billing
- credentials, secrets or access rights
- permissions, repository or service settings
- irreversible data changes
- anything that makes the project public
- a new dependency, or a change to a protected path
- any decision only the person can make

Added for this project:

- anything touching billing, payment, API keys or the Anthropic account
- a live Claude call outside a recorded cassette
- the CI workflow or anything under `.github/`
- `LICENSE` or the package metadata (`pyproject.toml` name, version, authors), publishing to PyPI or a plugin marketplace

## Lessons

- Tests build fixtures in `tmp_path` (or rely on the `tests/conftest.py` clean-up), never in place under `tests/fixtures`. In a restricted worktree, set `UV_CACHE_DIR` to a writable temporary folder if uv's default cache is read-only.
- A new engine option needs a caller in a real build path in the same issue, or it ships unused; a command that appends to a record needs a run-twice test.
- Run `uv run mypy` after a change under `src`: the strict-mode test in `tests/judge/test_p0_1_tooling.py` fails on untyped helpers. `lxml` needs `# type: ignore[import-untyped]`; a pydantic field named `copy` shadows `BaseModel.copy`. BSD `sed -i` needs an empty suffix argument.
- Any text field read from a person's or agent's file (rule, message, recipient, banned term) needs a blank and whitespace check where it is read; an empty string otherwise matches everything or is accepted silently.
- An outside Office reader must tolerate missing optional parts (theme, notes, relationships), catch archive errors including `zlib.error` and `BadZipFile`, and report a clean one-line exit-2 message; seed missing-part and corrupt-archive fixtures. XML declaration refusals need UTF-16 and UTF-32 fixtures with valid encoded controls: searching for ASCII bytes misses their declarations and readers can silently truncate text at an entity reference. For command input files (index, findings, manifest), cover malformed, empty and missing-key cases as `tests/test_cli_look_hostile_files.py` does.
- A rule or check keyed by section must use `section_key(section, index)` from `checks/engine.py`, never `section.id`, or sections without an id collapse into one finding or never fire.
- A change that removes or relaxes a refusal must update the skills, `docs/DESIGN.md` and PLAN.md deviations in the same issue, or they keep promising the old behaviour.
- When an issue supersedes a PLAN.md deviation, edit or delete the old line in the same issue rather than appending a new one.
- An issue already implemented on the loop branch is closed by checking its tests pass, not rebuilt.
- Fields added to the composition or plan models must be optional with a fallback, because older versions on disk lack them.
- A column of single letters can be upright multiline text: preserve the PDF text transform in facts instead of guessing rotation from word positions; measure wrapped labels at their actual column width. For quarter-turned PDF glyphs, pdfplumber's `size` is their advance, not their font size; use their cross-axis extent and group rotated lines before joining letters. Measure each column label separately: a chart-wide fit test turns short labels when one category is long.
- A text field supported by checks must survive both composition and example reconstruction, including `spoken`; test from a stored version after changing the working file. A shared rule-test fixture may cover both bullets and body text; choose its check field per example rather than copying text between fields in the engine. Composition stores an absent bullet head as `""`; restore it to `None` for rule testing, while keeping empty bodies that source checks do see.
- Word headings can be empty while their bookmarks remain; validate a cleared title before treating an empty section as a deletion. PowerPoint shape names split at the final slash: section ids can contain slashes, but field paths cannot.
- Match a Word item's unchanged body suffix before its head prefix: a revised head may extend the old head and either field may contain colons. Text written to Word or PowerPoint XML must have XML-illegal characters stripped, or the copy crashes the build.
- Find a rule example's version boundary before normalising paths or validating the id: splitting at the final slash loses id parts, `Path` consumes `./` and repeated slashes, and a final slash may belong to the id.
- The skill's gather agent returns facts with `source`; the engine's `Fact` model uses `source_key`. CLI acceptance tests must use the agent's shape rather than silently renaming its keys.
- CONTEXT.md's core table is locked to 23 terms by `test_p0_8_context.py`; add new skill vocabulary under `## Skill words` rather than extending that table.
- The parser extracts bullet citations but keeps prose citations inline; the guard must exclude their metadata from claim and evidence tokens and check prose keys too, or locators become claims and can support later invented numbers. Seed citation errors in list items: `source.citations-resolve` currently reads item citations, not paragraph text; use a callout for a document fixture. Pair a clean reporting control with a defective build so every added case detects the missing report.
- Citation acceptance tests need both `[S3 p.6-7]` and `[S1, p. 12]`: whitespace-only matching already handles the former but misses the latter, including old-locator evidence and unknown keys. Name controls must remove the name from both sources and gathered facts, or another evidence channel can mask the defect; gathered facts may start with an isolated name. Sentence boundaries can have closing quotation marks before whitespace; seed curly and straight quotes in prose and bullets, with supported and unsupported name controls.
- Prefixing source text with its key hides the opening sentence boundary from the fact guard. Keep the key and text as separate evidence entries in every guard caller, and pair an ordinary-word control with a name check that fails without the implementation.
- ENGINE.md's working-file example uses the obsolete `parallel-set` intent; derive allowed intents per format from `render/chooser.yaml`, rather than copying that example into an authoring reference.
- A command that reads a JSON index turns malformed input into exit 2 with a one-line message; validate the container and its entries before formatting. Empty objects and strings iterate without an error, so seed both alongside a known finding when testing an array reader.
- Component scopes need `CheckContext.composition`: keep only the selected stored section alongside a reconstructed example, and compose approved working files with the normal chooser. Rechoosing a stored example can lose overrides or content-dependent choices. Validate all stored composition entries before selecting a section: a first-match lookup can hide a malformed later entry and wrongly accept a corrupt version. Callout/body marks: new role names (`callout-title`, `callout-item`, `paragraph`) keep `ai_docs_kit.checks.fit` off them; `field_index` needs the composition to map a no-items statement title.
- Pass JSON bytes directly to Pydantic validation: `read_text()` can raise `UnicodeDecodeError` before validation when a file ends inside a UTF-8 character. Seed a truncated multibyte character alongside an intact Unicode control through the CLI.
- Regex validation must reject non-string YAML values before execution; compiling only strings lets numbers, booleans and null reach `re.search` and produce a traceback. Check key presence so explicit null is not mistaken for an absent regex. Exercise the installed CLI to check the real exit code and stderr.
- Validate a brand change's required reason before `begin_change`; rejecting it in `record_change` leaves the branch and edits behind. Folder creation can fail before a brand or version exists: translate brand-root `OSError` to `BrandError` and version-write `OSError` to `_BuildFailed`, so a file occupying the folder path gives one stderr line and exit 2 without a traceback.
- PowerPoint duplicates retain the original shape name: a dictionary assignment by field path loses earlier wording before comparison. Keep the first box's wording and formats; report each later non-empty box as unplaced. Seed repeated text alongside an edit to the original. Native table text lives in DrawingML cell text bodies under a graphic frame, outside ordinary text boxes; seed populated later cells and an added text box as a reporting control.
- A missing hashed Word bookmark map needs a headless list after a known list as its defect fixture: a heading resets list continuation and hides the leak. Cover both a middle and a final unresolved section through `review read`, with an intact-map control.
- A rule id used as a filename can escape through parent segments or an absolute path; validating the theme after writing is too late, and failure clean-up can delete the overwritten file. Reject both slash forms in the proposal loader before either command writes markers or rules. Test original bytes outside `rules/learned` after both `rule test` and `rule adopt`, including successful adoption outside the theme and failed validation inside it. A refused replacement must restore the previously adopted rule byte for byte; seed a successful adoption before the invalid replacement through both commands.
